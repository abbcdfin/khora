#+TITLE: Khora: Secure Hardware Credential Bridge for Autonomous Agents
#+AUTHOR: Jian
#+DESCRIPTION: A secure hardware-anchored credential bridge system for autonomous agents and automated workflows.

* Introduction
Khora is a hardware-based solution for secure credential management. It eliminates the need for users to store sensitive credentials in plain-text configurations or local databases. By storing all credentials on a dedicated device that requires multi-factor authentication (MFA) via a mobile phone over Bluetooth, Khora ensures high security and ease of use for agents like =openclaw= and other automated systems.

The name comes from Plato's /khôra/ (χώρα), the receptacle that holds things without being one of them. *Khora* is the whole system; *KhoraVault* is the hardware device at its centre.

* Core Features
- **Secure Hardware Storage**: Credentials are stored on an encrypted, tamper-resistant hardware module.
- **Bluetooth Authentication**: The device remains locked until authenticated by a paired mobile phone via Bluetooth LE.
- **Multi-Interface Access**: Supports USB-C for host connection and Bluetooth for mobile interaction.
- **Brute-Force Protection**: Implements rate-limiting and self-destruct (optional/configurable) mechanisms after multiple failed authentication attempts.
- **Seamless Integration**: Provides a standardized interface (HID, Virtual Serial, or custom driver) for agents and CLI tools to request credentials securely.

** 1. KhoraVault (Hardware)
- Microcontroller with secure enclave or external TPM.
- Bluetooth Low Energy (BLE) module.
- USB-C interface.

** 2. Khora App (Mobile Authenticator)
- A dedicated app that manages device pairing and grants access via biometric or PIN authentication.

** 3. khorad (Host Service)
- A lightweight service/driver running on the host machine that communicates with KhoraVault to retrieve credentials upon request.

* Security Design
- **End-to-End Encryption**: Every link between the Khora app, KhoraVault, and the host is authenticated and encrypted.
- **Physical Security**: The device is designed to be tamper-evident.
- **Master Key Isolation**: The host never sees the master encryption key; it receives only the individual credential approved for a request.

Khora protects secrets at rest and against unapproved use; it does not protect a host that is already compromised. See [[file:docs/architecture_design.md][Architecture Design]] for the full threat model.

* Usage Scenario: openclaw
Instead of configuring =openclaw= with an API key in a =.env= file:
1. Plug KhoraVault into the USB port.
2. openclaw requests the API key from =khorad=.
3. KhoraVault notifies the Khora app via Bluetooth.
4. User approves the request on their phone (FaceID/Fingerprint).
5. KhoraVault releases the API key to openclaw over the secure USB channel.
